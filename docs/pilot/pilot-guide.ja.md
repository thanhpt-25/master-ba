# パイロット利用ガイド

MasterBA を実案件 1 件で試行するチーム向けのガイドです。English: [pilot-guide.md](pilot-guide.md)。
サーバー構築は [deployment-runbook.md](deployment-runbook.md)、評価は [scoring-checklist.md](scoring-checklist.md) を参照してください。

## MasterBA でできること

顧客の要望資料（テキスト、Word、PDF、Excel）を入力すると、V字モデルの成果物を工程ごとに、日本の SIer 標準レイアウトの Excel ブックとして作成します。

| 工程 | 成果物 |
|---|---|
| 業務要件定義 | 業務要件定義書 |
| システム要件定義 | システム要件定義書 |
| 基本設計 | 基本設計書、結合テスト仕様書、総合テスト仕様書 |
| 詳細設計 | 詳細設計書、単体テスト仕様書 |

各工程では、作成エージェントが原案を作成し、機械的なチェックで根拠のない記述を差し戻し（各要件は入力資料の該当行を引用していること）、QA エージェントが原案をレビューします。そのうえで、チームの担当者が工程をレビューし、承認するかコメントを付けて差し戻します。承認されるまで次の工程には進みません。

## 役割

| 担当 | MasterBA の権限 | 作業 |
|---|---|---|
| パイロット責任者 | 管理者 | プロジェクト作成、アカウント管理、コストの確認 |
| レビュー担当（PM、リーダー） | 承認者 | 入力資料のアップロード、工程の実行、顧客確認事項への回答、承認・差し戻し、変更管理票の判断 |
| その他のメンバー | 閲覧者 | 成果物とトレーサビリティの閲覧 |

## 1 週目の進め方

| 日 | 作業 | 担当 |
|---|---|---|
| 1 | 実案件から、小さめの要望資料（5〜30 ページ）を 1 つ選ぶ。社外に出せない氏名やデータは削除する。 | 責任者 |
| 1 | プロジェクトを作成する（プロジェクト → 新規プロジェクト、成果物の言語は日本語）。 | 管理者 |
| 1 | 概要の「次の作業」に従い、入力資料をアップロードして業務要件定義を実行する。 | 承認者 |
| 1〜2 | エージェントが起票した顧客確認事項に回答する。回答できないものは顧客に確認する。 | 承認者 |
| 2 | 「次の作業」から業務要件定義書を開き、全シートを確認して承認または差し戻しを行う。評価シートを記入する。 | 承認者 |
| 3 | システム要件定義を実行し、レビューと評価を行う。 | 承認者 |
| 4〜5 | 基本設計（結合テスト仕様書・総合テスト仕様書を含む）を実行し、レビューと評価を行う。 | 承認者 |
| 5 | 評価シートと、重要なレビュー指摘 5 件を MasterBA チームに送る。 | 責任者 |

詳細設計は、基本設計の承認後、2 週目に実施できます。

## ダッシュボードの使い方

- **次の作業**：概要の最上部に、プロジェクトがいま待っている作業が 1 つだけ、ボタン付きで表示されます。迷ったらここから始めてください。
- **レビュー**：成果物を開き、シートのタブ（表紙、改訂履歴、各内容シート、トレーサビリティ）を確認します。Excel で読みたい場合はダウンロードしてください。ページ末尾で次のどちらかを行います。
  - 承認：そのまま、または自分で軽微な修正をすれば顧客に提出できる場合。
  - コメントを付けて差し戻す：1 行に 1 件記入します。行頭に `DOC-SRS-0001#item.3: この要件は 2 つに分けること` のように項目 ID を書くと、その項目への指摘になります。エージェントは指摘された箇所だけを修正し、新しい版をレビューに回します。
- **顧客確認事項**：顧客にしか決められない点は、エージェントが推測せずに確認事項として起票します。回答は、回答者と場（例：「田中様、11/25 定例」）とともに記録してください。回答は以降のすべての工程で確定事項として使われます。
- **承認後の変更**：変更管理票を起票します。承認前に成果物全体への影響範囲を確認でき、承認して反映すると、影響を受けるすべての成果物の新しい版を作成し、各改訂履歴に理由を記載します。

## 補足

- Word・PDF・Excel の入力資料はテキストに変換して保存し、要件はその行番号を引用します。引用がおかしいと感じたら、業務要件定義書の「出典」列で変換後のテキストを確認してください。
- 表紙の押印欄（承認・確認・作成）は空欄のままです。押印にご利用ください。
- テスト仕様書の「判定」「実施日」「実施者」「不具合ID」はテスト担当者の記入欄です。ブックを再出力すると消えるため、テスト結果はコピーに記録してください。
- 合意に至らない実行は、品質の低い成果物を出さずに停止します（エスカレーション）。「次の作業」から 1 回再開するか、MasterBA チームに連絡してください。

## フィードバックしていただきたいこと

1. 工程ごとに記入した[評価シート](scoring-checklist.md)
2. 差し戻し時のレビューコメント
3. 顧客に提出できないと感じたレイアウト上の点（不足シート、列の違い、表現など）
4. 手作業で作成する場合と比べた、レビューにかかった時間
